## 1. 核心研究問題

一張 GPU 的實體顯示記憶體容量，不一定等於它可以在特定軟體架構下完成的 AI 工作負載上限。HAVEFUN 研究如何提升**有限 VRAM 硬體的任務可完成性**，並在多個不同計算節點之間協同處理可拆分的工作。這不代表 GPU 的原始算力、顯存容量或記憶體頻寬被物理改變。

Q-Framework 以 QmRNA、QVRAM、QSTATIC 等技術家族研究低記憶體執行與計算狀態延續；Temporal Möbius 則以工作結果和資源條件評估候選運算路線。公開文件僅描述功能目標與已驗證現象，**不揭露實現這些功能的專有方法**。

## 2. 第一條證據：單張 RTX 2080 Ti 已實際完成 H3 運算

**顯卡條件：**RTX 2080 Ti，記憶體擴充版，單張約 22 GB（非原廠 11 GB 配置）。

- **Studio #370 與 #371：**單張 GPU 完成 MiniMax H3 原生短片生成，取得可解碼 MP4。這兩次是短片工作負載，並不是 15 秒單次採樣。
- **Job #365：**單張 GPU 依序完成十個短時間生成區塊，後續組裝為 **15 秒、360 幀**影片，總耗時 **3 小時 12 分 08 秒**。過程發生 **9 次 CUDA OOM**，部分區塊重新提交後完成。這證明單卡的**分段產線可完成性**，不等於「沒有任何 OOM」或「單次原生 15 秒採樣成功」。
- **2026-10-26 單卡 1080p 正式成片：**單張記憶體擴充版 RTX 2080 Ti 22GB，10／10 支原生 1088×1920 H3 RS 成功，無升頻裁切並組成 **1080×1920、5 秒、120 幀、24fps MP4**；本輪**零 CUDA OOM 紀錄**、總耗時 **1 小時 39 分 16 秒**。已驗證成片規格與完整性，視覺品質待 Owner 驗收。這是分段生成後組片，不是單次 120 幀採樣。

單卡能力是獨立研究成果，不能以四卡產線的數字替代，也不能把不同解析度或不同長度的任務直接比較速度。

## 3. 第二條證據：同張 GPU 的 QmRNA 對照實驗

在同張擴充 22GB RTX 2080 Ti、相同參考輸入與 Seed、**480×832、36 幀、24fps、10 Steps** 的受控實驗中：

| 路徑 | 觀察 |
|---|---|
| 基準執行路徑 | Step 1 進入 **PRE-OOM** 保護條件，未交付預期的單 Worker MP4 |
| 啟用 QmRNA 保護的路徑 | 完成全部 10 Steps，成功產生 MP4，該輪未記錄 CUDA HARD_OOM |

這支持一項具體技術結論：在已測定條件下，**執行策略的差異改變了工作能否完成**。PRE-OOM 是軟體事前保護事件，不等同硬體已發生 CUDA Out-of-Memory 例外；這項實驗也不能外推為所有模型、所有影片都永久不會 OOM。

**核心實現方法保密。**可供審查的是輸入範圍、結果、比較設計、證據等級與失敗邊界；完整配置、原生接入細節、控制策略和底層收據不公開。

## 4. 第三條證據：四 GPU 叢集實際交付效率

正式 Job **#361** 使用**四張獨立 22GB RTX 2080 Ti** 執行十個影片生成區塊，配合 CPU 後製，完成：

| 項目 | 已記錄成果 |
|---|---|
| 最終影片時長 | 15.000 秒 |
| 幀數與幀率 | 360 幀／24fps |
| 最終影片畫布 | 480×832（9:16） |
| 實際參與的 GPU | 四張獨立 RTX 2080 Ti 22GB |
| 端到端交付時間 | **14 分 37 秒** |
| 成品驗收 | MP4 可完整解碼，幀數及時長符合該次任務 |

這是**端到端影片工作流**成果，不能當成單張 GPU 的原生採樣速度，更不能與 1080p 的其他測試直接比較。四卡的 VRAM 為**分散的獨立資源**，並非一張可直接定址的 88GB GPU。

## 5. 計算延續、輸出一致性與數學驗證

其他獨立控制實驗包括：

- 跨 GPU 的 20-Step 數值延續與對照結果位元一致，測得最大絕對差異 **0.0**。
- 約 **250 MiB** 計算狀態搬運，來源與目標驗證摘要一致。
- QmRNA 受控 22 幀影片比較，**22／22 個解碼影格一致**。
- Windows 與 Mac 不同設備之間，已有分散數學計算、獨立結果驗算及有限規模模型權重訓練實驗。

每項實驗的條件不同，不得把「受控狀態搬運成功」寫成「所有模型都已具備任意異卡無縫接續」，也不得把局部模型學習寫成真正通用自主 AI 已完成。

## 2026-10-26｜單卡 1080p H3：原生高解析 RS 與完整 5 秒成片均已成功

**正式實測：單張擴充至 22GB 的 RTX 2080 Ti，已經完成 MiniMax H3 的 1080p 等級原生高解析度影片運算，並交付完整 5 秒 MP4。** 本次使用 Q 系列輔助的單卡執行路徑；有原生 RS 運算、媒體規格與成片雜湊完整性的獨立收據。

| 項目 | 經核對的單卡成果 |
|---|---|
| GPU | **RTX 2080 Ti 22GB 擴充版 ×1**（不是原廠 11GB 版） |
| 原生 MiniMax H3 RS | **10／10 支成功**；每支原生生成 **1088×1920、22 幀** |
| 正式交付 | **1080×1920、9:16、5.000 秒、24fps、120 幀 MP4** |
| 解析度處理 | 只裁切並截幀（每 RS 交付 12 幀）；**沒有升頻** |
| 本輪 CUDA OOM | **0 次紀錄** |
| 整體耗時 | **1 小時 39 分 16 秒** |
| 驗證 | 十支原生 RS 成功回執、最終影片規格及雜湊完整性驗證；**視覺品質仍待 Owner 驗收** |

因此本成果同時證實：**(1) 單張 2080 Ti 可完成原生 1080p 等級 H3 RS 運算；(2) 同張卡的分段運算可完成真正的 1080×1920、5 秒成片。**原生片段的 1088×1920 是 GPU 真正生成的解析度；交付 1080×1920 是無升頻裁切。這不是把低解析度影片升頻，也不是一次單獨採樣完整 120 幀。

**嚴格區分：**影片的 5 秒是播放長度，**不是 5 秒內運算完成**；本輪共耗時 1 小時 39 分 16 秒。「本次未記錄 OOM」不代表所有模型永久不 OOM。Q 系列輔助路徑成功不等於已獨立證實任何單一 QVRAM 卸載／恢復機制的因果作用。Owner 另回報未啟用 Q 的相關 H3 工作 OOM，仍待配對其原始失敗收據。

**BlackBox：**僅公開數值、範圍與成果級別。內部模型接入、演算法、私有素材、原始 Prompt、客戶資料與完整控制策略皆不公開。

## 6. 異質超級電腦神經網絡：最終研究願景

HAVEFUN 期望建立跨 GPU、CPU、不同作業系統與獨立計算設備的智慧運算網絡。研究方向不只包含工作分配，也包括安全的狀態保存、結果驗算、歷史經驗累積及依據觀察結果修正決策。

**已獲得的工程基礎：**單卡 H3 成片、同卡低記憶體對照、四卡影片交付、跨裝置數值一致性，以及特定範圍的數學與模型學習實驗。

**尚待驗證與擴大：**全網持續自主學習、任意異世代 GPU 的通用模型狀態恢復、無人工介入的普適決策能力，以及對 H100/H200 在相同工作負載下的完整效能比較。

## 6A. 多節點異質運算計劃（Multi-Node Compute Roadmap）

**目的：**讓 Temporal Möbius 在 Owner 授權下協調 Windows／macOS、GPU／CPU 與不同型號硬體，使數學推理、影音分段生成、成果驗算、學習回饋等工作能依能力分配。**本章描述工程路線圖，不等於整套八節點影音原生推論已完成。**

### 架構：一個計劃，三類職責

| 職責 | 公開功能與預期成果 | 狀態 |
|---|---|---|
| Master／調度層 | 接收授權任務、拆成可驗證子工作，依資源條件派送並蒐集回執，保留 Owner 暫停／取消／回滾控制 | 已有多卡影片產線證據；跨主機統一調度持續整合 |
| Brain／推理與品質層 | 使用不同 macOS 裝置執行數學、推理、候選策略比較與結果評分；目標逐步擴至四台 Brain | 分散數學與有限訓練實驗已進行；常態閉環尚未全面驗證 |
| Windows／GPU＋CPU Worker 層 | 依設備能力接受單段 H3 或其他可切分任務、回報狀態與結果；目標逐步擴至四台 Windows Worker 主機 | 四張 GPU 的特定影片產線成功；跨主機通用 Worker 協定仍在驗證 |

**目標配置：四台 macOS Brain ＋ 四台 Windows Worker 主機，總計八台異質裝置。**這是目標設備數，**不是已驗證八機同步運算，更不是八張 GPU 或單張 88GB 顯卡**。既有四卡交付是四張各自獨立的 22GB RTX 2080 Ti 協作，與未來八主機拓樸不同。

### 工作閉環：以回執證明每一步

`Owner 授權 → Master 拆解／派工 → Brain 評估 + Worker 執行 → 分段回執與一致性驗算 → CPU／GPU 成片 → 品質評分／失敗回饋 → 下次任務決策`

- 每一工作單元都需可追蹤 **Task／RS 識別、節點狀態、完成或失敗、耗時與可驗證輸出**；對外僅公開聚合後的匿名證據。
- 調度與恢復目標包含心跳、逾時偵測、重試冪等、防重複領取、不同裝置相容性及離線復原；**這些是驗收要求，不宣稱現已普遍實現**。
- QmRNA／QVRAM／QSTATIC／QAnswer 與 Temporal Möbius 分工可合作，但私有狀態格式、記憶體調度與模型接入方式仍為 **BlackBox Owner-only**。
- 系統不得擅自把未授權設備加入運算；授權、停止、回滾及證據保留均受 Owner 控制。

### 分階段工程里程碑

| 階段 | 驗收重點 | 公開證據級別 |
|---|---|---|
| **P0 已完成的基礎** | 單卡 1080p／5 秒完成，#361 四 GPU 480p／15 秒交付，受控數學與狀態一致性實驗 | **已驗證特定工作負載** |
| **P1 一台跨主機 Worker 閉環** | 身份相容、領題、實算、提交結果、回執、心跳、失敗回復及獨立重驗 | **進行中的整合目標** |
| **P2 八裝置擴展** | 四 Brain＋四 Windows Worker 的可見在線狀態、分流、負載測量、節點隔離與回退 | **計劃，待實機全鏈驗收** |
| **P3 自主驗算與學習** | 每次學習後自動生成隔離 Smoke、Master／Möbius 評分、比較輸出品質與速度，形成回饋閉環 | **研究計劃；不可當成通用 AI 已完成** |
| **P4 公開基準驗收** | 同任務下公開成功率、各節點耗時、失敗／OOM 次數與成果一致性 | **待資料核驗後發佈** |

**衡量準則：先確認能否完成，再衡量時間與效率。**完整的跨主機調度、GPU 原生計算跨異卡任意接續，以及全網自主學習能力，目前不得用既有四卡影片成功案例代替證明。

公開多節點架構頁與圖像：[Multi-node architecture](../site/multi-node.html) · [公開計劃](../docs/multi-node-roadmap.md)。所有原始節點名稱、位址、Worker 連線方式、鑑權資訊及私人生成素材不公開。
