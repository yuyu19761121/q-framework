## RC4.3 — BlackBox 公開研究版（日本語）

**研究テーマ：単一GPUにおけるAI処理の実行可能性、異種GPU協調、異種スーパーコンピュータ・ニューラルネットワーク**  
**2026年10月｜独自実装と非公開の検証資料はオーナーが管理**

## 1. 中心となる研究課題

GPUの物理的なVRAM容量は、特定のソフトウェア方式で**実際に完了可能なAIタスクの絶対上限**と必ずしも同じではない。HAVEFUNは限られたメモリを持つハードウェアにおける**タスク実行可能性**を研究し、さらに独立した計算資源の協調を目指す。

Q-Frameworkの研究分野にはQmRNA、QVRAM、QSTATICによるメモリを考慮した実行・計算継続性、Temporal Möbiusによる経験を利用した経路判断が含まれる。これらは各技術の役割を表す説明であり、**独自のアルゴリズムや実装手順は公開しない**。ソフトウェアでGPUの物理的な演算性能、帯域幅やVRAM容量が増えるという主張ではない。

## 2. 証拠軸①：単一のRTX 2080 TiでH3動画生成に成功

**ハードウェア：**VRAMを約22GBに拡張したRTX 2080 Ti。メーカー標準の11GB仕様とは区別する。

- **Studio #370／#371：**単一GPU上でMiniMax H3のネイティブ短尺動画生成に成功し、再生可能なMP4を取得した。15秒の単発ネイティブ推論ではない。
- **Job #365：**1基のGPUが10個の短いネイティブ生成区間を順に実行し、**15秒／360フレーム**の映像にまとめた。総処理時間は**3時間12分08秒**。途中で**9回のCUDA OOM**が発生し、対象区間を再投入して完成した。これは**単一GPUによる分割生産ライン**の実証であり、「OOMゼロ」や「360フレーム一括サンプリング成功」ではない。
- **2026年10月26日：単一GPUで1080p完成動画を確認：**RTX 2080 Ti 22GB×1で、ネイティブ **1088×1920 H3 RSを10/10個**完成。アップスケールせずクロップ・トリミングして **1080×1920、5秒、120フレーム、24fps MP4**を生成。CUDA OOM記録**0回**、所要**1時間39分16秒**。最終動画規格と整合性を検証済み、画質はオーナー評価待ち。単発120フレームのネイティブサンプリングではない。

単一GPUの成功は、4GPUの高速納品とは別個の成果である。異なる解像度・長さ・リトライ条件の実験を同一条件の速度比較として扱わない。

## 3. 証拠軸②：同一GPUにおけるQmRNA比較試験

同じVRAM拡張版22GB RTX 2080 Ti、同じ参照データとSeed、**480×832、36フレーム、24fps、10 Steps**の条件で実施した統制試験：

| 経路 | 観測結果 |
|---|---|
| ベースライン | 最初のStepで**PRE-OOM**保護条件に入り、期待された単独ワーカーMP4を納品できなかった |
| QmRNA保護経路 | 全10Stepsを完了し、MP4を生成。該当実行にはCUDA HARD_OOMの記録がない |

これは指定条件において**実行方式の違いがタスクの完成可否を変えた**ことを示す限定的な成果である。PRE-OOMは事前保護条件であり、実際のCUDA Out-of-Memory例外と同義ではない。すべてのH3タスクでOOMが永久に起きないという証明でもない。

具体的な実装、内部状態や制御方式は非公開とする。外部で評価可能なのは比較条件、結果、証拠の種類および制約である。

## 4. 証拠軸③：4基の独立GPUによる実際の動画納品

正式Job **#361**では**4基の独立したRTX 2080 Ti 22GB**が10個の生成区間を処理し、CPUによる編集を加えて完成した。

| 項目 | 記録された結果 |
|---|---|
| 動画の長さ | 15.000秒 |
| フレーム | 360フレーム／24fps |
| 完成動画サイズ | 480×832、縦長 |
| GPU | 独立した22GB版RTX 2080 Ti×4 |
| エンドツーエンド | **14分37秒** |
| 成果物 | MP4のデコードおよびフレーム数・時間を確認 |

これは動画制作フロー全体の実績であって、単一GPUの推論速度ベンチマークではない。異なる1080pワークロードと直接比較することもできない。4基の22GB VRAMは**独立したメモリ**であり、1基の直接アドレス可能な88GB GPUではない。

## 5. 計算継続と数値的一貫性

別々の統制実験から、以下の結果が得られている。

- GPU間で20 Stepsの数値計算を継続し、対照とビット単位で一致。最大絶対差 **0.0**。
- 制御されたデバイス間整合性の研究を実施。内部データ量および検証手法は非公開。
- QmRNAの限定的な動画比較で、**22／22枚のデコード画像が一致**。
- WindowsとmacOSの計算ノードによる数学分割、独立検算、限定的なモデル重み更新の実験。

これらはすべて同じ動画Job内で起きたものではない。すべてのモデル・GPU世代で自由に状態を復元できることや、汎用自律AI完成の証拠にはならない。

## 2026年10月26日｜単一GPUで1080p級H3ネイティブ計算と5秒完成動画に成功

**実際のネイティブ処理と完成動画のレシートを確認：** VRAM拡張版 **RTX 2080 Ti 22GBを1基だけ**使用し、Qシリーズ支援のMiniMax H3ワークフローで、**ネイティブ高解像度RSを10個すべて生成し、1080×1920の5秒MP4を完成**した。

| 項目 | 検証済み単一GPUの実績 |
|---|---|
| GPU | **VRAM拡張版RTX 2080 Ti 約22GB×1**（標準11GB版ではない） |
| ネイティブMiniMax H3 RS | **10/10成功**、各RSは**1088×1920／22フレーム**で原生生成 |
| 完成動画 | **1080×1920、9:16、5.000秒、24fps、120フレーム MP4** |
| 納品時の処理 | 各RSを12フレームにトリミングし、クロップのみで**アップスケールなし** |
| CUDA OOM記録 | **0回**（本実行のみ） |
| 総所要時間 | **1時間39分16秒** |
| 検証内容 | ネイティブRS実行と完成映像の規格・ハッシュ整合性。**画質はオーナー確認待ち** |

これは**単一GPUの1080p級ネイティブH3処理と、1080pの完成5秒動画の両方が成立した**成果である。原生解像度は1088×1920で、1080×1920への変換は拡大でなくクロップである。120フレームを一度のネイティブサンプラーで生成したわけではない。

**適用範囲：**5秒は映像の再生時間で、**5秒で生成したことは意味しない**。実際は1時間39分16秒。全モデル・全GPUでOOMが起きない保証や、特定のQVRAM物理オフロードの単独因果検証は主張しない。QなしH3のOOMは別途オーナーからの報告であり、原生エラーレシートの照合を要する。

**BlackBox：**独自コード、モデルへの内部接続、判断手法、私的プロンプトとメディアは公開しない。

## 6. 最終目標：異種スーパーコンピュータ・ニューラルネットワーク

HAVEFUNは、所有者が許可した複数のGPU、CPU、ワークステーションなどを、検証可能な計算タスク、保護された状態、履歴と判断フィードバックによって結ぶ研究を進めている。

**確認済みの基礎：**単一GPUのH3動画、同GPUのQmRNA比較、4GPUによる動画納品、数値状態の継続性、異種ノードの数学検算と小規模なモデル学習。

**今後の検証課題：**ネットワーク全体の継続的な自律学習、任意のGPU世代間の汎用ネイティブ状態復元、幅広い環境で信頼できる自動判断、H100／H200との完全な同条件の性能比較。

## 6A. 異種マルチノード計算計画（公開ロードマップ）

**目的：**オーナーの許可したタスクを Windows／macOS、CPU／GPU、推論・評価ノードへ割り振り、数学、推論、動画RS、検証、学習フィードバックを連携させる。**本節は計画であり、8台同時のネイティブ動画推論が完成したという意味ではない。**

| 層 | 役割 | 現在の証拠 |
|---|---|---|
| Master／調整 | 許可済みタスクの分割・割当・レシート集約、オーナーによる停止とロールバック | 限定的な4GPU動画パイプラインは検証済み。一般的なホスト間調整は統合中 |
| Brain／推論・品質 | 数学、推論、候補経路の比較、品質評価と学習フィードバック。macOS機器4台を目標 | 限定的な分散数学・モデル学習の実験。常時自律閉ループは未検証 |
| Windows GPU／CPU Worker | 対応可能な動画RS・数値タスクの実行、進捗と結果の返送。Windowsホスト4台を目標 | 独立GPU4基の特定動画完成は実証済み。汎用のホスト間Worker協定は検証中 |

**目標はmacOS Brain 4台＋Windows Workerホスト4台の計8台の異種デバイス**。8台すべての同時実行完了やGPU8基を示すものではない。#361のGPU4基での動画生成実績と将来の8ホスト構成は別の主張であり、4基の22GB VRAMが単一の88GB VRAMになるわけでもない。

**計画する閉ループ：**

`Ownerの許可 → Masterのタスク／RS分割 → Brain評価＋Worker実行 → 結果レシート・独立検算 → 成果物・品質確認 → フィードバック → 次回経路の判断`

各タスクには追跡可能な識別子、ノード状態、成功／失敗、処理時間、出力検証が必要。ノード認証の互換性、ハートビート、タイムアウト、重複実行防止、切断復旧、独立検証、Ownerの中止／復元は**今後の受入基準**であり、普遍的に完成済みとは主張しない。QmRNA／QVRAM／QSTATIC／QAnswer／Temporal Möbius の独自処理はBlackBoxのままとする。

| 段階 | 受入基準 | 状態 |
|---|---|---|
| **P0 実測済みの基礎** | 単一GPU 1080p／5秒、#361 4GPU 480p／15秒、限定的な数値・整合性テスト | 限定条件で実証済み |
| **P1 1台の遠隔Worker** | 認証、タスク受領、計算、結果提出、レシート、心拍、失敗後の独立再検証 | 統合中 |
| **P2 8デバイスへの拡張** | Brain 4台＋Windows Worker 4台の接続・分散・隔離・復帰 | 計画段階 |
| **P3 学習／Smoke閉ループ** | 学習後の隔離Smoke、Master／Möbiusによる品質・速度評価 | 研究段階 |
| **P4 外部評価基準** | 実測の成功率、実行時間、OOM／障害、出力の整合性 | 検証後に公開 |

**成功可否を先に検証し、その後で速度、品質、信頼性と資源効率を比較する。**限定的な4GPU生成から、任意GPU世代間の普遍的な状態復元や完全自律ニューラルネットワークを証明したとは言えない。
